
# FamilyVault: A Comprehensive Project Overview

## 1. High-Level Vision & Concept

**FamilyVault** is a secure, private, and modern web application conceived as a **digital family scrapbook**. Its primary goal is to provide a dedicated and intimate online space where family members can collaboratively create a lasting archive of their most cherished memories.

In an era of public social media, FamilyVault offers a private alternative, focusing on the shared experiences that bind a family together. It's not just about storing photos; it's about preserving the stories, moments, and milestones that define a family's unique history.

---

## 2. Detailed Feature Breakdown

Every feature in FamilyVault is designed to be intuitive, engaging, and supportive of the core mission of memory preservation.

### 2.1. Authentication & User Onboarding

*   **Multi-Provider Sign-In:** Users can create an account and log in using two standard methods:
    1.  **Email & Password:** For users who prefer a traditional login.
    2.  **Google Sign-In:** For a quick and seamless experience using an existing Google account.
*   **Automatic Profile Creation:** Upon a user's first successful sign-in, a corresponding `UserProfile` document is automatically created in the Firestore database. This profile stores the user's display name, email, and their all-important `familyId`.

### 2.2. Family Group Management

This is the core of FamilyVault's privacy model. All content is scoped to a family.

*   **Create or Join:** After logging in, a user without a family is presented with two choices:
    1.  **Create a Family:** A user can create a new family group by giving it a name (e.g., "The Smith Family"). This user automatically becomes the designated "owner" of the family.
    2.  **Join a Family:** A user can join an existing group by entering the unique **Family ID** shared with them by another family member.
*   **Unique Family ID:** When a family is created, a unique, non-guessable ID is generated by Firestore. This ID is the "key" to joining the family, ensuring that only invited members can gain access. The ID can be easily copied to the clipboard for sharing.
*   **Member Visibility:** The "Family" page lists all current members of the group, showing their name and email, fostering a sense of community.
*   **Owner Privileges:** Only the designated family "owner" has the permission to delete the entire family group, a destructive action that is protected by a confirmation dialog.

### 2.3. The Photo Wall (Main Dashboard)

The dashboard is the heart of the application, designed to be visually engaging and emotionally resonant.

*   **Masonry-Style Layout:** Photos are displayed in a dynamic, multi-column grid that adjusts to different screen sizes. This avoids rigid rows and creates a more organic, "scrapbook" feel.
*   **Playful Rotation Effect:** Each photo card is given a slight, randomized CSS rotation (`-2deg`, `1deg`, `3deg`, etc.). This small touch breaks the grid's monotony and enhances the tangible, scrapbook aesthetic.
*   **Real-time Updates:** The dashboard is built with a real-time listener on the Firestore `photos` collection. When a family member uploads a new photo, it appears on the Photo Wall for *all other online family members instantly*, without anyone needing to refresh their page.
*   **Tag-Based Filtering:** At the top of the wall, all unique tags from all photos are displayed as filter buttons. A user can click a tag (e.g., "vacation") to instantly filter the grid and see only the photos associated with that tag.

### 2.4. Photo Upload & Storytelling

*   **File Selection:** Users can select a photo from their device via a standard file input. The UI is designed to be intuitive, with a large drag-and-drop area.
*   **Add a Note:** A textarea allows users to add a story, a caption, or a simple note to the photo, preserving the context of the memory.
*   **Tagging:** A text input allows users to add comma-separated tags (e.g., `summer 2024, beach, birthday`). These tags are automatically converted to lowercase and stored as an array, powering the filtering system.
*   **Progress Indication:** During the upload, a progress bar provides visual feedback to the user, letting them know their memory is being securely saved.

### 2.5. Special Days & AI-Powered Creativity

*   **Milestone Tracking:** This feature allows families to log important recurring dates like birthdays and anniversaries.
*   **Generative AI for Theme Suggestions:** This is a unique feature powered by **Google's Genkit**.
    *   When adding a special day, a user specifies the event type (e.g., "Birthday").
    *   They can click a "Suggest Theme" button, which triggers a Genkit flow.
    *   The AI model receives the event type and returns a list of creative, one-word theme suggestions (e.g., `fireworks`, `confetti`, `balloons`, `photo album`).
    *   These themes can be used to inspire automated memory collections or special UI treatments for that day.

## 3. Technology Stack & Architecture

FamilyVault is built on a modern, robust, and scalable full-stack technology architecture.

*   **Framework: Next.js (with App Router)**
    *   **Why?** The App Router enables a powerful new paradigm with React Server Components, which are used by default to improve performance by reducing the amount of JavaScript sent to the client. It also provides a clear and organized file-based routing system.

*   **Language: TypeScript**
    *   **Why?** TypeScript provides static typing for JavaScript, which drastically reduces bugs, improves code quality, and enables superior developer tooling and auto-completion.

*   **Backend & Database: Firebase**
    *   **Firebase Authentication:** Manages all user sign-up and sign-in flows. It's a secure, managed service that handles the complexities of authentication.
    *   **Firestore:** A real-time, NoSQL database. It is the single source of truth for all application data, including user profiles, family groups, and photo metadata. Its real-time capabilities are essential for the instantaneous updates on the Photo Wall.
    *   **Firebase Storage:** A scalable and secure object storage service used to store the actual photo files uploaded by users.
    *   **Firebase Security Rules:** A critical component that secures the backend. Rules are written to ensure that users can only access data belonging to their own family, enforcing the application's privacy model.

*   **Generative AI: Genkit**
    *   **Why?** Genkit is a portable, open-source framework for building AI-powered features. It provides a structured way to define AI flows, prompts, and schemas, making the integration of Large Language Models (LLMs) clean and maintainable. In FamilyVault, it's used to power the creative theme suggestions.

*   **UI Components & Styling**
    *   **ShadCN UI:** This is not a traditional component library but a collection of beautifully designed, accessible, and unstyled components that can be copied directly into the project. This provides maximum flexibility and ownership over the code. Key components used include `Card`, `Button`, `Dialog`, `Input`, and `Tabs`.
    *   **Tailwind CSS:** A utility-first CSS framework that allows for rapid and consistent styling directly within the HTML. It's used for all styling, from layout to colors.
    *   **Color Palette:** The UI uses a custom theme defined with HSL CSS variables in `src/app/globals.css`.
        *   **Primary (`--primary`):** A soft, inviting purple (`270 50% 65%`), used for key interactive elements like buttons and highlights.
        *   **Background (`--background`):** A gentle, off-white (`0 0% 96%`) for a clean and airy feel.
        *   **Accent (`--accent`):** A subtle, complementary shade (`300 26% 86%`) used for hover states and secondary information.
    *   **Typography:**
        *   **Headlines (`--font-headline`):** `Playfair Display`, a serif font that evokes a classic, elegant, and timeless "scrapbook" feeling.
        *   **Body (`--font-body`):** `PT Sans`, a clean and highly readable sans-serif font used for all descriptive text and UI labels, ensuring clarity.
    *   **Icons:** `lucide-react`, a library of simple, clean, and consistent icons used throughout the application to enhance usability.

## 4. Project & Code Structure

The project follows the standard Next.js App Router structure.

*   `src/app/`: The main directory for all pages and layouts.
    *   `(app)/`: A route group for all authenticated pages (Dashboard, Upload, etc.). `layout.tsx` within this group contains the shared sidebar and header.
    *   `page.tsx`: The main landing/login page.
*   `src/components/`: Contains all the React components.
    *   `ui/`: The ShadCN UI components.
    *   `auth/`, `family/`, `photos/`, etc.: Application-specific components, organized by feature.
*   `src/firebase/`: Centralizes all Firebase-related code.
    *   `config.ts`: Stores the Firebase project configuration keys.
    *   `provider.tsx` & `client-provider.tsx`: Manages Firebase initialization and provides context to the entire app.
    *   `firestore/`: Contains custom hooks like `useCollection` and `useDoc` for interacting with Firestore.
*   `src/contexts/`: Home to React Contexts, like `auth-provider.tsx`, which manages and provides global access to the current user's authentication state and profile.
*   `src/ai/`: Contains all Generative AI code.
    *   `genkit.ts`: Initializes and configures Genkit.
    *   `flows/`: Contains specific Genkit flows, like `suggest-theme-templates.ts`.
*   `firestore.rules` & `storage.rules`: The security rules that protect the Firebase backend resources.
*   `tailwind.config.ts`: Configuration file for Tailwind CSS, where the custom font families are defined.
*   `docs/backend.json`: A blueprint file defining the data structures (entities) and Firestore collection paths for the application, used as a reference for code generation and consistency.
